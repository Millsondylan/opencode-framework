# Decision Records: 2026-04-21

This file is appended by `subagent_stop.py` after each pipeline subagent completes. The hook extracts the agent name, the exit status, and a short context and decision summary from the subagent output, then writes a new entry at the end of this file. The format follows a Michael Nygard ADR lite template trimmed to the five fields that make sense at subagent granularity: timestamp, agent name, exit status, decision, and rationale. Full architecture decision records (ADR 0001 through ADR 0030) live alongside this file in `docs/decisions/ADR-NNNN-slug.md` and are written by humans or by the plan agent.

The file is append only. Existing entries must never be modified by the hook. The hook must not reorder entries. Entries are sorted naturally by the timestamp at the head of each entry. Any tooling that reads this file can parse each entry by splitting on the `## [` anchor at column zero.

The `subagent_stop.py` hook must validate that every entry it writes conforms to the canonical entry format defined below. Entries that fail validation are written to `docs/decisions/_quarantine.md` instead so that this file never contains malformed records.

## Canonical Entry Format

Every entry written to this file by `subagent_stop.py` must follow the template below exactly. The `YYYY-MM-DDTHH:MM:SS` timestamp is UTC in ISO 8601 basic form without timezone suffix. The agent name is the value of the `name` field in the agent frontmatter. The exit status is the integer exit code returned by the subagent, where zero indicates success and any non zero value indicates failure. The four subsections (Context, Decision, Rationale, Related) are mandatory. Each subsection body is one to four sentences of prose or a short bullet list. No subsection may be empty.

```
## [YYYY-MM-DDTHH:MM:SS] agent-name (exit N)

### Context
[brief]

### Decision
[brief]

### Rationale
[brief]

### Related
[files/ADRs referenced]
```

Field rules:

1. The timestamp bracket and agent name line is an H2 heading (`## `) at column zero.
2. The four subsections are H3 headings (`### `) at column zero, in the order Context, Decision, Rationale, Related.
3. The body of each subsection begins on the line immediately following the heading. A blank line separates subsections.
4. The Related subsection lists files and ADR identifiers. File paths are absolute from the repository root. ADR identifiers follow the `ADR-NNNN` pattern and may include the slug (for example `ADR-0012-event-sourcing`).
5. The entry ends with a blank line before the next entry begins. Two consecutive H2 anchors without the separating blank line are a format violation.

Characters outside the ASCII printable range and the `\n` newline are not permitted. In particular the em dash (U+2014), en dash (U+2013), figure dash (U+2012), and horizontal bar (U+2015) are banned by rule 08. The hook replaces any occurrence with an ASCII hyphen before writing.
